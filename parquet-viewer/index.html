Parquet Viewer

Open a Parquet file to see its schema and rows. The file is read in your browser and never uploaded.

How it works

Your file stays on your device

When you open a file, your browser reads it straight from disk. The viewer reads only the parts it needs: the footer that holds the schema and metadata, then the column data for the rows you scroll to. Nothing is uploaded.

The browser enforces it

The page sets a Content Security Policy that blocks all network connections (connect-src 'none'), images and form submissions. The only things it may load are the library files listed below, at exact versions from jsDelivr. Each file also has an integrity hash, and the browser refuses any file whose contents don't match. The policy and the hashes are in the page source.

To check for yourself, watch the Network tab in your browser's developer tools while you open a file: no requests appear. Or load this page, go offline, then open a file.

Libraries

  • hyparquet 1.31.5 reads the Parquet metadata and rows.
  • hyparquet-compressors 1.1.2 adds decompression for gzip, Brotli, Zstd, LZ4 and Snappy.
  • fzstd 0.1.1 decompresses Zstd.
  • hysnappy 1.1.1 decompresses Snappy using a small WebAssembly module. The module imports nothing, so it can't call any browser API. Compiling it is what 'wasm-unsafe-eval' in the policy allows.

What you see

The line above the table shows the file's size, row and column counts, how many row groups the rows are stored in, and the compression used. The table starts with the first 100 rows and loads 100 more each time you scroll near the bottom. Column headers show each column's type.

  • 64-bit integers are shown at full precision.
  • Timestamps are shown in ISO 8601 format to the millisecond, marked as UTC. DATE columns are shown as dates.
  • Binary values are shown as text if they are readable UTF-8, and otherwise as hex: the first 16 bytes and the total length.
  • Lists, structs and maps are shown as JSON.
  • Long values are cut off. Hover over a cell to see all of it.

Limitations

  • It's read-only: no filtering, sorting or queries.
  • Supported compression is none, Snappy, gzip, Zstd, Brotli and LZ4. Encrypted files aren't supported.
  • Columns with lists, structs or maps are read a whole row group at a time, so scrolling deep into a very large file with nested columns can be slow.
